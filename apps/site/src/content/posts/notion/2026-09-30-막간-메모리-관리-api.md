## ✦ 메모리 관리 API

- 어떻게 메모리를 할당하고 관리해야 하는가.

### ◆ 메모리 공간의 종류

- 메모리 공간
    - stack : 컴파일러에 의해 암묵적으로 할당 & 반환이 되는 메모리
        - 자동 (automatic) 메모리
        - 변수 선언 시 컴파일러가 자동으로 공간 확보.
        - 지역 변수
        
        ```c
        void func() {
        	int x; // stack 에 int 형 선언
        }
        ```
        
    - heap : 프로그래머에 의해 명시적으로 할당 & 반환이 되는 메모리
        
        ```c
        void func() {
        	int *x = (int *) malloc(sizeof(int));
        	...
        }
        ```
        
        - stack & heap 할당이 모두 발생

### ◆ `malloc()` 함수

- `malloc()` : heap 에 요청할 공간 크기 넘겨주기
    - 성공 : 새로 할당된 공간 포인터 반환
    - 실패 : NULL 반환

```c
#include <stdlib.h>

void *malloc(size_t size);
```

- `stdlib.h` 를 include 해야 함

```c
double *d = (double *) malloc(sizeof(double));
```

- 정확한 크기의 공간을 요청하기 위해 `sizeof()` 연산자 사용
- 문자열 선언할 때는 NULL 위해서 1 바이트 더함
- 반환 : `void` 포인터 → 프로그래머가 명시적으로 타입 변환 (type casting)

### ◆ `free()` 함수

- 더 이상 사용하지 않는 heap 메모리 해제

```c
free(x);
```

### ◆ 흔한 오류

- 많은 언어들은 자동 메모리 관리 (automatic memory management) 지원
    - garbage collector
- 오류들
    - 메모리 할당 잊어버리기 (segmentation fault)
        
        ```c
        char *src = "hello";
        char *dst;
        strcpy(dst, src); // segfault
        ```
        
    - 메모리 부족하게 할당 받기 (buffer overflow)
    - 할당받은 메모리 초기화하지 않기 (uninitialized read)
    - 메모리 해제하지 않기 (memory leak)
    - 메모리 사용이 끝나기 전에 메모리 해체하기 (dangling pointer)
    - 반복적으로 메모리 해체하기 (double free)
    - `free()` 잘못 호출하기 (invalid frees)

### ◆ 운영체제의 지원

- `brk` : 프로그램의 break 위치 변경
    - break : heap 의 마지막 위치
- `sbrk` : 증가량만을 받음
- `mmap()` : OS 로부터 메모리 얻기

- 사용자 요구 분석 -> 특정 [[데이터베이스 관리 시스템|DBMS]] 로 [[데이터베이스|DB]] 구현
- [[데이터 모델]] 기반 [[스키마]] 확정 절차

### 고려 사항
| 항목 | 내용 |
| --- | --- |
| 무결성 | 삽입, 삭제, 갱신 후에도 [[데이터]]가 제약 조건 만족 |
| 일관성 | DB 데이터, 질의 대한 응답이 처음부터 끝까지 일정 |
| 회복 | 시스템 장애 시, 장애 발생 직전 [[state\|상태]]로 복구 가능 |
| 보안 | 불법적 데이터 노출 · 변경 · 손실로부터 보호 |
| 효율성 | 응답시간 단축, 시스템 생산성, 저장 공간 최적화 가능 |
| DB 확장 | DB 운영에 영향 X 면서 지속적 데이터 추가 가능 |

### 절차
1. 요구 조건 분석
2. 개념적 설계 : 정보 모델링, 개념화
	- 개념 [[스키마]] 모델링 + [[트랜잭션]] 모델링 병행 수행
	- 요구 조건 명세 -> DBMS 독립적 [[E-R 모델|E-R 다이어그램]] 설계
	- 독립적 개념 스키마 설계
3. 논리적 설계 : 데이터 모델링
	- 목표 DBMS 맞는 논리 스키마 설계
	- 트랜잭션 [[인터페이스 설계]], [[관계형 데이터베이스]] -> 테이블 설계
4. 물리적 설계 : 데이터 구조화
	- 목표 DBMS 맞는 물리적 구조 데이터로 변환
	- DB 파일 저장 구조 · 액세스 경로 결정
	- 고려 사항 : 트랜잭션 [[Throughput|처리량]], 응답 시간, 디스크 용량, 저장 공간 효율화
5. DB 구현
	- 목표 DBMS 의 DDL (데이터 정의어) 로 DB 생성
	- [[트랜잭션]] 작성, 응용 프로그램 작성

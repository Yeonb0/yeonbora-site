- [[정규화]] 된 [[데이터]] 모델 통합 · 중복 · 분리 과정
- 의도적으로 정규화 원칙 위배
- 성능 ↑ 효율성 ↑ / 일관성 · 정합성 ↓
- 과도 -> 성능 ↓

### 방법
1. 테이블 통합
	- 두 테이블 하나로 합치기
	- 1 : 1 관계, 1 : N 관계, 슈퍼타입 / 서브타입 테이블 통합
	- 검색 간편, 레코드 [[Throughput|처리량]] ↑, 입력 · 수정 · 삭제 간편
	- 제약 조건 (Constraint, Default, Check) 설계 难
2. 테이블 분할
	- 수평 분할 (Horizontal Partitioning)
	- 수직 분할 (Vertical Partitioning)
		- 갱신 위주 속성 / 자주 조회 속성 / 크기 ↑ 속성 / 보안 적용 속성
	- [[기본키]] 유일성 관리 难, 수행 속도
3. 중복 테이블 추가
	- 경우
		- 정규화로 수행속도 ↓
		- 많은 범위 데이터 자주 처리
		- 특정 범위 데이터 자주 처리
		- 처리 범위 ↓ -> 수행 속도 개선
	- 방법 : 집계 테이블 +, 진행 테이블 +, 특정 부분 테이블 +
4. 중복 속성 추가
	- 데이터 조회 경로 단축 -> 자주 사용 [[속성]] 추가
	- 경우
		- 조인 자주 발생
		- 접근 경로 복잡
		- 액세스 조건으로 자주 사용
		- 기본키 형태 적절 X, 여러 속성 구성
	- 고려
		- 테이블 · 속성 중복
		- 일관성 · [[무결성]]
		- [[SQL]] 그룹 [[함수]] 이용
		- 저장 공간 낭비

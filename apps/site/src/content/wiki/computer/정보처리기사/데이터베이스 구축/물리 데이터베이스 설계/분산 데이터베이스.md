- 논리적으로 1 시스템, 물리적으론 [[컴퓨터 네트워크|네트워크]] 통해 연결된 여러 컴퓨터 사이트에 분산된 [[데이터베이스]]

### 장 · 단점
| 장점 | 단점 |
| --- | --- |
| 지역 자치성, 효용성 · 융통성 ↑ | [[데이터베이스 관리 시스템\|DBMS]] 수행 기능 복잡 |
| 자료 공유성, [[Reliability\|신뢰성]] · 가용성 ↑ | DB 설계 难 |
| 분산 제어 可, 시스템 용량 확장 Good | [[소프트웨어]] 개발 비용 ↑ |
| 시스템 성능 ↑ | 처리 비용 ↑ |
| 중앙 장애 -> 전체 시스템 영향 X | 잠재적 [[Error\|오류]] ↑ |

### 구성 요소
| 요소 | 내용 |
| --- | --- |
| 분산 처리기 | 자체적 처리 능력 O, 지리적 분산 O 컴퓨터 시스템 |
| 분산 데이터베이스 | 지리적 분산 DB, 해당 지역 특성 맞게 DB 구성 |
| 통신 네트워크 | 분산 처리기 통신망 연결 -> 논리적으로 한 시스템처럼 작동 |

### 목표
| 목표 | 내용 |
| --- | --- |
| 위치 투명성(Location Transparency) | 실제 위치 X, DB 논리적 명칭 만으로 액세스 可 |
| 중복 투명성([[레플리케이션\|Replication]] Transparency) | 동일 [[데이터]] 중복 -> 사용자는 1개처럼 사용, 시스템 자동 여러 개 수행 |
| 병행 투명성(Concurrency Transparency) | 다수 [[트랜잭션]] 동시 실현 -> 결과 영향 X |
| 장애 투명성(Failure Transparency) | 트랜잭션 · [[데이터베이스 관리 시스템\|DBMS]] · 네트워크 · 컴퓨터 장애 있어도 트랜잭션 정확히 처리 |

### 설계
- 목적 : App or 사용자 -> 분산 저장 데이터 접근하도록
1. 테이블 위치 분산 : DB 테이블 각기 다른 [[서버]] 분산 [[배치 처리|배치]]
2. 분할(Fragment) : 테이블 데이터 분할해 분산
	- 완전성(Completeness) : 전체 데이터 대상 분할
	- 재구성(Reconstruction) : 관계 [[연산]] 활용 -> 재구성 가능해야 함
	- 상호 중첩 배제(Dis-jointness) : 분할 데이터 -> 서로 다른 분할 항목 X
3. 할당(Allocation) : 동일 분할 여러 [[서버]] 에 생성하는 분산 방법

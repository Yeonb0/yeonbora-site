- [[트랜잭션]] 수행 도중 장애 발생해 [[데이터베이스|DB]] 손상 시 손상 이전 정상 [[state|상태]]로 복구하는 작업

### 장애 유형
| 유형 | 내용 |
| --- | --- |
| 트랜잭션 장애 | 입력 [[데이터]] [[Error\|오류]] · 불명확 데이터 · 시스템 자원 과다 요구 등 트랜잭션 내부 비정상 상황 -> 프로그램 실행 중지 |
| 시스템 장애 | DB 손상 X but 하드웨어 오동작 · [[소프트웨어]] 손상 · [[교착상태]] 등 모든 트랜잭션 연속 수행 장애 |
| 미디어 장애 | 저장장치 디스크 블록 손상 · 디스크 헤드 [[Collision\|충돌]] 등 DB 일부 or 전부 물리적 손상 |

### 회복 관리기
- [[DBMS]] 구성 요소
- 트랜잭션 실행 성공적 완료 X -> DB 모든 변화 취소(Undo) & 수행 이전 원상 복구
- [[메모리]] 덤프 · 로그(Log) 이용 회복 수행

### 회복 기법
| 기법 | 내용 |
| --- | --- |
| 연기 갱신 기법 (Deferred Update) | 트랜잭션 성공적 완료까지 DB 실질적 갱신 연기, 갱신 내용 Log 보관 -> 부분 완료 시점에 실제 DB 기록, Rollback 시 Undo 필요 X -> Redo 만 O |
| 즉각 갱신 기법 (Immediate Update) | 데이터 갱신 -> 실제 DB 즉시 반영 + 갱신 내용 Log 보관, 회복 시 Undo & Redo 모두 O |
| 그림자 페이지 대체 기법 (Shadow Paging) | 갱신 이전 DB 를 일정 크기 페이지 단위 구성 + 페이지마다 그림자 페이지 보관, Rollback 시 실제 페이지에 그림자 페이지 대체, 로그 · Undo · Redo 필요 X |
| 검사점 기법 (Check Point) | 갱신 내용 · 시스템 상황을 검사점 로그 보관, 장애 시 검사점부터 회복 -> 회복 시간 절약 |

# 허브 위쪽 검색 · 오른쪽 위키 입구 설계

작성 : 2026-11-27
목업 : 대화에서 확인한 `search-mockup.html` A안 (양쪽에서 밀려오는 결과)

## 1. 의도

허브의 가장자리 입구 (아래 프로필 · 왼쪽 블로그) 에 오른쪽 위키와 위쪽 검색을 더한다. 검색 결과는 허브의 방향 문법을 이어 왼쪽 = 블로그, 오른쪽 = 위키로 나눈다.

## 2. 정한 것

- 오른쪽 입구 : 오른쪽 가장자리에 0.45s 머물기 · 누르기 · 터치는 오른쪽 끝에서 왼쪽으로 쓸기 → 위키 바탕색 (#232236, registry 의 wiki fill) 이 오른쪽에서 차오른 뒤 `/wiki/`
- 위쪽 입구 : 위쪽 가장자리 (양 옆 64px 은 왼쪽 · 오른쪽 입구 자리라 뺀다) 에 머물기 · 누르기 · `/` · Ctrl / Cmd + K · 터치는 위쪽 끝에서 아래로 쓸기 → 검색창이 위에서 내려오고 허브가 어두워진다
- 입력하면 블로그 결과는 왼쪽에서, 위키 결과는 오른쪽에서 밀려와 화면을 반씩 채운다. 각 쪽 머리에는 아이콘 (도서관 책 · 위키 점) 과 결과 수만, 설명글 없음
- 결과 항목 : 제목 · 본문 미리보기 두 줄 (검색어 근처부터) · 칩 (블로그는 인문 / 기술, 위키는 카테고리) · 블로그는 날짜. 검색어는 보라 밑줄 형광펜
- 순위 : 모든 낱말이 들어 있는 것만, 제목이 같음 > 제목 시작 > 제목 포함 > 별칭 · 태그 > 본문
- 키보드 : Enter 는 가장 잘 맞는 결과로, ↓ 로 결과 목록, ↑ ↓ 이동, ← → 로 반대쪽 목록, Esc 로 닫기. 검색어가 없을 때 어두운 바깥을 누르면 닫힌다
- 색인 : 빌드 때 `/search-index.json` (블로그 글 + 위키 노트, 본문은 마크다운 · 표 · 수식 기호를 걷어낸 앞 400자). 위쪽 입구에 마우스가 닿을 때 미리 받는다
- 모바일 (640px 이하) : 블로그 · 위키 결과를 위아래로 이어 함께 스크롤하고, 결과가 없는 쪽은 짧게

# Layered Wiki 프로젝트 페이지 설계 (데모데이 무대)

작성 : 2026-11-27
관련 저장소 : 이 저장소 (yeonbora-site), 하니스 저장소 https://github.com/Yeonb0/layered-wiki-harness (demo_ui · serve/demo_api.py)

## 1. 의도

실전 AI 에이전트 수업 16주차 데모데이 (2026-12-16 · 12-18) 에서 관리자님이 발표 PC 로 yeonbora.dev 를 열고, 프로젝트 방의 Layered Wiki CD 에서 들어가 **발표 · 시연 · 설명을 한 페이지에서 오가며** 발표한다. 보는 사람은 교수님과 청중이고, 프로젝터 화면으로만 본다. 일반 방문자용 포트폴리오는 이번 목표가 아니다.

지금은 시연 화면이 `localhost:5173` (Vite dev 서버) 에서만 뜨고, 발표 자료는 따로 있다. 이것을 사이트 안의 한 무대로 모은다.

## 2. 목표 · 비목표 · 반목표

목표
- 프로젝트 방 CD → `/projects/layered-wiki/` 로 들어간다
- 한 페이지에 세 탭 : 발표 (HTML 슬라이드) / 시연 (demo_ui) / 설명 (주차별 산출물 위키)
- 탭을 바꿔도 각 탭의 상태 (슬라이드 위치, 시연의 보는 사람 · 진행 중 라이브 투입, 설명의 열린 주차) 가 남는다
- 시연은 발표 PC 의 시연 API (`localhost:8090`) 를 불러 실제로 동작한다

비목표
- 다른 기기 (교수님 · 청중 노트북, 휴대폰) 에서 시연이 동작하는 것. 다른 기기에서는 안내만 보인다
- 시연 API · 모델 · Dify 를 외부에 여는 것 (터널, 클라우드 서버)
- 슬라이드의 내용 (무엇을 몇 장에 말할지). 이 문서는 틀만 다루고, 내용은 따로 정한다
- 모바일 최적화. 깨지지 않을 정도면 된다

반목표 (동작해도 실패로 본다)
- 프로젝터 화면에 탭 막대 · 버튼 같은 UI 가 늘 떠 있는 것
- 탭을 바꿨더니 시연 상태가 초기화되는 것 (라이브 투입 중이면 특히)
- 시연 화면이 사이트 CSS 와 섞여 레이아웃이 달라지는 것
- demo_ui 코드가 두 저장소에 따로 존재해 갈라지는 것
- 시연 화면이 층 구분 없는 단일 위키처럼 보이는 것 (하니스 지침 7절 방어선)

## 3. 제약

- 사이트 : Astro 7 정적 빌드, Cloudflare (wrangler, `apps/site/dist`) 에 이미 배포되어 있다. 섹션 규칙은 README 의 "새 섹션 추가" 를 따른다.
- 프로젝트 방 CD 는 지금 `data.ts` 의 `href` 를 `window.open(..., '_blank')` 로 연다 (`room.ts` openPage).
- demo_ui : Vite + React 19, 하니스 저장소에 있다. API 주소는 `VITE_API_BASE` 로 받는다. 글꼴은 `/fonts/nanumsquareneo/` 의 OTF 를 쓰는데 저장소에는 없다 (OFL 재배포 조건 결정, 2026-10-23).
- 시연 API : `serve.demo_api`, `--cors-origin` 은 값 하나만 받는다. `/health` 가 있다. 화면만 보일 때는 임베딩 서버 (:8082) 가 필요하고, 라이브까지는 생성 서버 (:8081) · Dify 가 더 필요하다 (claude/시연 화면 보여주는 법).
- 하니스 지침 3절 18 ~ 22 : 합성 시연 코퍼스이며 측정 결과가 아님을 밝힌다. 시연 경로 변경이 실험 경로를 건드리지 않는다. 보는 사람별 거르기는 서버 쪽이다 (이 설계는 화면을 옮길 뿐 거르기를 바꾸지 않는다).
- Chrome 은 공개 사이트 (https) 가 localhost 를 부를 때 로컬 네트워크 접근 허용을 묻는다. iframe 안에서 부를 때는 iframe 에 그 권한을 넘겨야 할 수 있다.
- 코드 규칙 : 들여쓰기 2칸, 배열 · 자료구조 변수는 대문자 시작, 주석 끝 마침표 없음, 화면은 다크 모드 (#1a1a1a / #e0e0e0 계열).

## 4. 접근 (시연 화면을 넣는 방식)

| 안 | 내용 | 대가 |
|---|---|---|
| **A. 빌드 결과 복사 + iframe (선택)** | 하니스에서 demo_ui 를 사이트 하위 경로 · `VITE_API_BASE=http://localhost:8090` 으로 빌드해 `apps/site/public/projects/layered-wiki/demo/` 에 복사. 시연 탭은 같은 출처 iframe | demo_ui 를 고칠 때마다 다시 빌드 · 복사 (스크립트). iframe 에 포커스가 있으면 바깥 단축키가 안 먹어서 연결 코드가 필요 |
| B. 소스를 사이트로 옮겨 React 섬 | demo_ui 를 사이트 컴포넌트로 | 같은 코드가 두 저장소에, @xyflow · d3 유입, 사이트 전역 CSS 충돌 |
| C. 서브모듈 · 워크스페이스 패키지 | 하니스를 묶어 import | Cloudflare 빌드에 서브모듈, npm / pnpm, TS 5.9 / 6 혼재. 데모데이 직전에 빌드 구조를 흔듦 |

관리자님이 A 를 골랐다. 이유 : demo_ui 원본을 하니스 저장소 하나에 지키면서 (지침의 "시연 프론트는 분리된 디렉터리") 가장 적게 바꾸고, iframe 이 CSS · 키 입력을 자연스럽게 나눈다.

함께 정한 것
- 시연은 발표자 혼자 조작한다 (청중이 각자 기기로 조작하는 안은 고르지 않음). 그래서 외부에 여는 것이 없다.
- 탭 구조 (A : 한 덱 안에 시연 장 넣기) 대신 탭 셋 + 하단 막대를 골랐다.
- 설명은 제출본 · 최신판 나란히 (설명 + 시연 나란히 안 대신). 시연은 화면 전체가 필요하고, 설명 탭은 질의응답에서 "무엇이 바뀌었나" 를 보여 주는 데 쓰기 때문.

## 5. 정해진 것

### 5.1 들어가는 길

- 프로젝트 방의 Layered Wiki CD `href` 를 `/projects/layered-wiki/` 로 바꾼다.
- 사이트 안 주소는 새 탭이 아니라 같은 탭에서 연다 (`href` 가 `/` 로 시작하면 `location` 이동, 아니면 지금처럼 새 탭). *Claude 판단* : 발표 중 탭이 늘어나지 않게.
- 페이지에서 저장소 링크 (layered-wiki-harness) 는 설명 탭 머리에 둔다. *Claude 판단*

### 5.2 화면 틀

```
평소                                마우스를 화면 아래 끝으로
┌──────────────────────┐           ┌──────────────────────┐
│                      │           │                      │
│ 발표 / 시연 / 설명      │    →     │                      │
│ (지금 탭이 화면 전체)    │           ├──────────────────────┤
│                      │           │ [발표 7/15] [시연 ●] [설명] │
└──────────────────────┘           └──────────────────────┘
```

- 세 탭은 처음에 모두 만들어 두고 보이기 / 숨기기만 한다 (언마운트 금지). 시연 iframe 도 숨긴 채 살아 있다.
- 하단 막대는 평소 숨김. 마우스가 화면 맨 아래 좁은 띠 (약 8 ~ 12px) 에 닿으면 올라오고, 막대를 벗어나면 내려간다. 띠를 좁게 두는 이유 : 시연 화면 아래쪽 버튼을 누를 때 막대가 가리지 않게.
- 막대 내용 : `발표 n / 전체`, `시연 ●` (연결 상태), `설명`. 지금 탭 강조.
- 키보드
  - `1` · `2` · `3` : 발표 · 시연 · 설명으로 전환
  - `←` `→` (또 PageUp / PageDown, 발표용 리모컨 대응) : 발표 탭에서만 슬라이드 이동
  - `F` : 전체 화면 켜기 / 끄기
  - 입력창 (input, textarea, select, contenteditable) 에 포커스가 있으면 위 단축키를 모두 무시한다. demo_ui 의 회의록 붙여 넣기 · 문서 고르기에서 숫자가 탭 전환으로 새지 않게
- iframe 안에 포커스가 있을 때도 `1` `2` `3` `F` 가 먹어야 한다. 같은 출처 iframe 이므로 부모가 iframe 의 `contentWindow` 에 keydown 을 붙인다 (demo_ui 코드는 고치지 않는다). 방향키는 시연 탭에서 iframe 에 그대로 둔다.
- 상단의 사이트 홈 버튼 (Base.astro) 은 이 페이지에서 끈다 (`showHome={false}`). *Claude 판단* : 프로젝터에 떠 있는 UI 를 없애려고. 홈으로는 막대 끝의 작은 링크로 간다.

### 5.3 시연 탭

- iframe `src = /projects/layered-wiki/demo/index.html`, `allow` 에 로컬 네트워크 접근 권한을 넘긴다 (정확한 토큰 이름은 빌드 시점 Chrome 문서로 확인).
- 연결 확인 : 부모가 `http://localhost:8090/health` 를 주기적으로 부른다 (*Claude 판단* : 5초). 결과로 막대의 `●` 색을 바꾼다 (연결 초록 / 끊김 빨강).
- 끊김으로 바뀌는 순간 막대를 3초 올렸다 내린다. 숨긴 막대 때문에 서버가 꺼진 것을 놓치지 않게.
- 처음 열었을 때 연결이 안 되면 iframe 대신 안내를 보인다 : "시연은 발표 PC 에서 시연 API 를 켜야 동작합니다" + 필요한 서버 목록 (임베딩 :8082, 시연 API :8090, 라이브는 :8081 · Dify 추가). 연결되면 iframe 으로 바꾼다. 이 안내가 다른 기기에서 보이는 화면이다.
- 시연 경고 줄 (합성 코퍼스 · 메커니즘 시연이며 측정 결과 아님) 은 demo_ui 대시보드에 이미 있으므로 사이트에서 따로 넣지 않는다.

### 5.4 demo_ui 빌드 · 복사

- 사이트 루트에 스크립트 하나 : `pnpm demo:sync <하니스 저장소 경로>`.
  1. `<경로>/demo_ui` 에서 `npm ci` (lock 있음) 후 `VITE_API_BASE=http://localhost:8090 npx vite build --base /projects/layered-wiki/demo/ --outDir <임시>`
  2. `apps/site/public/projects/layered-wiki/demo/` 를 비우고 결과를 복사
  3. 복사한 하니스 커밋 해시를 `demo/VERSION` 에 남긴다 (어느 demo_ui 가 올라갔는지 추적)
- 빌드 결과물은 사이트 저장소에 커밋한다 (Cloudflare 빌드가 하니스를 몰라도 되게).
- 하니스 저장소의 vite 설정 · 소스는 바꾸지 않는다 (`--base` 는 CLI 로).
- 글꼴 : 나눔스퀘어네오 OTF 는 복사하지 않는다. 사이트가 이미 네이버 CDN 의 nanum-square-neo.css 를 쓰므로, iframe 에서도 그 글꼴이 잡히는지 확인하고 안 잡히면 system-ui 로 보이는 것을 받아들인다 (*Claude 판단* — 재배포 결정 유지).

### 5.5 시연 API 실행

- 발표 때 여는 주소는 `https://yeonbora.dev` 하나로 정한다 (이미 배포됨). 리허설도 배포된 사이트에서 한다. 로컬 (`pnpm dev`, localhost:4321) 에서 볼 때는 `--cors-origin http://localhost:4321` 로 띄운다고 실행 문서에 두 줄로 적는다. *Claude 판단* : 시연 API 는 출처를 하나만 받고 하니스 코드는 바꾸지 않기로 했으므로.
- 시연 순서 문서의 탭 4 명령에서 `--cors-origin http://localhost:5173` 을 `--cors-origin https://yeonbora.dev` 로 바꾼다. 하니스 코드 변경 없음.
- 리허설 때 Chrome 의 로컬 네트워크 접근 허용을 한 번 해 둔다.
- 하니스 쪽 문서 (claude/시연 화면 보여주는 법) 의 탭 5 (화면 dev 서버) 는 사이트로 대체되었다고 고친다.

### 5.6 설명 탭 (주차별 산출물 위키)

수업 사이트의 "개인별 프로젝트" 위키 (목차 + 주차별 페이지) 를 본뜬다.

```
┌──────────┬──────────────────┬──────────────────┐
│ 목차      │ 제출본 (날짜)       │ 최신판 (날짜)       │
│ 1주 ...   │                  │                  │
│ ▸7주 설계  │   본문            │   본문             │
│ ...      │                  │                  │
└──────────┴──────────────────┴──────────────────┘
```

- 왼쪽 목차 (주차 순), 오른쪽에 제출본 · 최신판 두 창. 각 창 위에 판 이름과 날짜.
- 두 창은 따로 스크롤한다.
- 한 창의 머리글을 누르면 그 판만 넓게, 다시 누르면 둘로.
- 판이 하나뿐인 주차는 한 창만 넓게 보이고 "제출본 그대로" 라고 표시.
- 주차를 고르면 주소 해시 (`#w07`) 를 바꾼다. 새로고침해도 그 주차로.
- 원본 위치 : `apps/site/src/sections/layered-wiki/weeks/<주차>-<판>.md` (예 : `07-submitted.md`, `07-latest.md`), frontmatter `week`, `title`, `edition: submitted | latest`, `date`. 이 폴더만 읽는 별도 content collection `layeredWikiWeeks` 를 둔다. *Claude 판단* : `src/content/` (Obsidian 볼트) 밖에 두어 위키 링크 그래프 · 깨진 링크 리포트 · 기존 스키마에 섞이지 않게 한다. 같은 내용의 두 판이 그래프에 둘씩 생기는 것을 막고, 데모데이 전에 콘텐츠 파이프라인을 건드리지 않으려는 것이다. 본문의 `[[ ]]` 링크는 변환하지 않는다.
- 본문의 흐름도 · 그림은 `_assets/layered-wiki/` 에 둔다. Mermaid 가 있으면 빌드 때 SVG 로 바꾼다 (*방식은 빌더 판단*).

### 5.7 발표 탭 (틀만)

- 16 : 9 고정 비율 무대 하나를 화면 가운데 꽉 차게 키운다 (남는 곳은 #1a1a1a).
- 슬라이드 한 장 = Astro 컴포넌트 하나 (`src/sections/layered-wiki/slides/NN-이름.astro`), 순서는 파일 이름. *Claude 판단* : 표 · 다이어그램 · 큰 숫자처럼 장마다 배치가 달라서 마크다운보다 컴포넌트가 맞음.
- 이번 범위에는 표지 1장 + 예시 1장만 넣는다. 내용은 별도 대화에서.
- 지금 장 번호를 주소 해시 (`#s7`) 에 남긴다.

## 6. 진행 단계 (Phase, vertical slice)

| Phase | 목표 | 완료 기준 |

### 9.4 시연 서버 (Cloud Run)

컨테이너 하나에 다음을 담는다. 이미지는 하니스 저장소에서 만든다 (`deploy/demo-cloudrun/`, 실험 경로 코드와 분리된 폴더).

- 하니스 `serve.demo_api` (Python), 미리 돌린 볼트 `demo900_propose_20261022_193431` (합성 시연 코퍼스, 스냅샷 900). 실제 코퍼스 · 실험 로그는 넣지 않는다.
- 임베딩 : 같은 컨테이너 안의 llama.cpp `llama-server` + `bge-m3-Q8_0.gguf` (CPU). 미리 돌린 볼트를 만든 것과 같은 임베딩 모델이라 검색 결과가 로컬 시연과 같게 유지된다. *Claude 판단* : 외부 임베딩 API 를 쓰면 계정이 하나 더 늘고 벡터가 달라진다.
- 생성 : OpenRouter (`https://openrouter.ai/api/v1/chat/completions`). 주의 : 미리 돌린 볼트를 만든 Qwen3-8B (`qwen/qwen3-8b`) 는 OpenRouter 에서 2026-10-09 지원 종료 예정으로 공지되어 있었다. 같은 모델을 못 쓰면 미리 돌린 볼트 (로컬 Qwen3-8B) 와 라이브 투입 (다른 모델) 의 모델이 달라지므로 화면 고지에 둘 다 적는다. 키는 Secret Manager 에 두고 환경 변수로 넘긴다. 이미지 · 저장소 · 화면에 키를 넣지 않는다.

Cloud Run 설정

- 최대 인스턴스 1 : 라이브 작업 상태 · 회의 데이터가 메모리 · 컨테이너 파일에 있으므로 두 대로 나뉘면 안 된다. 지금의 409 Busy (한 번에 한 건) 가 그대로 유지된다.
- CPU 상시 할당 : 응답을 돌려준 뒤에도 도는 작업 (라이브 투입 · 회의록 투입) 이 멈추지 않게.
- 최소 인스턴스 0. 데모데이 (12-16 · 12-18) 와 리허설 날만 1 로 올려 첫 요청 대기를 없앤다.
- 요청 시간 한도는 라이브 1건 (로컬 실측 약 90초) 을 넉넉히 넘게.
- 리전 : 도쿄 (asia-northeast1). *Claude 판단* : Cloud Run 도메인 매핑을 지원하는 가장 가까운 리전이고 (서울 asia-northeast3 은 미지원), 1등급 요금 리전이라 더 싸다. 확인 : Cloud Run locations 문서 (https://docs.cloud.google.com/run/docs/locations)
- 컨테이너 파일은 재시작 때 사라진다 : 회의 데이터 · 투입 결과는 재시작하면 시드 상태로 돌아간다. 시연에는 오히려 맞다 (리허설 흔적이 남지 않음).

주소

- 시연 API 주소는 `https://demo-api.yeonbora.dev` (Cloud Run 도메인 매핑 + yeonbora.dev DNS 에 CNAME). 매핑이 막히면 Cloud Run 기본 주소 (`*.run.app`) 로 대신하고, 사이트 쪽은 주소 한 줄 (`data.ts` 의 `ApiBase`, demo:sync 의 `VITE_API_BASE`) 만 바꾼다.
- 시연 API 의 `--cors-origin https://yeonbora.dev`.
- Chrome 로컬 네트워크 허용이 더는 필요 없다 (localhost 를 부르지 않음).

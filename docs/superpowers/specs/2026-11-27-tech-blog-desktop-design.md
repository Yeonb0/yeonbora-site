# 기술 블로그 (/posts/) 바탕화면 설계

작성 : 2026-11-27
시안 : https://claude.ai/artifact/4sJvPpNc6r9U9qPU1da9Qk (바탕화면 + 폴더 창 보드)

## 1. 의도

허브 왼쪽 가장자리의 "기술 블로그" 입구 (`HubLayout.astro`, href `/posts/`) 로 들어오면, 깃블로그 (Bora.log) 의 색감을 이어받은 컴퓨터 바탕화면이 뜬다. 카테고리 폴더를 누르면 창이 열리고, 그 카테고리의 글을 책 (시리즈) 단위로 찾아 읽는다. 지금 `/posts/` 는 임시 목록 (`서재`) 이다.

## 2. 목표 · 비목표 · 반목표

목표
- 왼쪽 : 카테고리 폴더 14개 (최근 글 + 깃블로그 카테고리 13개), 폴더마다 다른 선 글리프
- 가운데 : 글 목록 창. 처음에는 Network 폴더가 열려 있다. 닫기 버튼은 없고 늘 폴더 하나가 열려 있다
- 오른쪽 : 연 폴더 안의 책 (시리즈) 아이콘. 책이 둘 이상이면 맨 앞에 "전체", 시리즈 밖 글이 있으면 맨 뒤에 "시리즈 밖의 글"
- 책이 하나뿐인 폴더는 그 책이 선택된 채로 열린다
- 글 카드 : 제목 · 본문 앞 두 줄 · 날짜 · 태그 + 오른쪽 썸네일 칸 (카테고리 글리프 + 시리즈 안 순서 표시). 카드 / 한 줄 보기 전환
- 최근 글 : 최신 8편, 제목 위에 `카테고리 / 시리즈 / 순서`
- BOJ : 티어 폴더 (전체 · Bronze · Silver · Gold · Platinum, 깃블로그 사이드바 색) + 최신 순 목록
- 폴더를 바꾸면 창이 이전 폴더 쪽으로 줄었다가 새 폴더 자리에서 커지며 열린다 (반동 없음, 0.15s + 0.26s)
- 모바일에서도 쓸 수 있다

비목표
- 글 페이지 (`/posts/[slug]`) 디자인 변경. 이번에는 목록 화면만 바꾼다
- 검색 기능 동작. 검색 입력창은 자리만 두고, 서재 검색은 Phase 2 에서 붙인다
- 썸네일 이미지. 지금은 글리프 칸이고, 대표 이미지는 나중에 정한다

반목표
- 같은 카테고리의 두 시리즈가 한 목록에 섞여 구분되지 않는 것
- 단어 중간에서 줄이 바뀌는 것 (`word-break: keep-all`)
- 노랑이 한 화면에 여러 군데 반복되는 것 (노랑은 시리즈 / 책 표시에만)

## 3. 제약

- 글은 `posts` collection (`src/content/posts/`) 에서만 읽는다. 지금 옮겨진 글은 1편이라 대부분 폴더가 비어 있다. 빈 폴더는 빈 상태 안내를 보여 준다. 글 옮기기 (M4) 가 진행되면 그대로 채워진다
- 기술 블로그에는 `field: computer` 글만 놓는다. 인문 글은 `/humanities/` 도서관이 맡는다
- 홈 버튼 (서재 책갈피 리본) 은 이미 고른 것이라 그대로 둔다
- 방 구조 규칙 : `sections/posts/` (Layout.astro + tokens.css) + `pages/posts/index.astro`

## 4. 접근

- A (선택) : `pages/posts/index.astro` 가 collection 을 읽어 가벼운 목록 데이터 (제목 · 날짜 · 태그 · 요약 · 카테고리 · 시리즈 · 순서 · 티어) 를 만들고, React 섬 `Desktop.tsx` 하나에 넘긴다. 폴더 · 책 선택 · 보기 전환 · 창 애니메이션은 섬 안의 상태로 처리한다
- B : 폴더 · 책마다 정적 페이지 (`/posts/network/컴퓨터-네트워크`) 를 만들고 View Transitions 로 넘긴다. 주소가 생기지만 창 애니메이션 (폴더 자리에서 열리기) 을 페이지 전환으로 흉내 내야 해서 복잡하다
- A 를 고른 이유 : 시안의 상호작용을 그대로 옮길 수 있고, 지금 글 수 (전부 옮겨도 약 430편) 면 한 페이지 데이터로 충분하다. 열린 폴더 · 책은 주소 해시 (`#network/컴퓨터 네트워크`) 에 남겨 공유 · 뒤로가기가 되게 한다

## 5. 콘텐츠 모델 변경

- `PostSchema` 에 `step` (시리즈 안 순서, 정수, 선택) 과 `tier` (BOJ 티어 : Bronze · Silver · Gold · Platinum, 선택) 를 더한다. 지금 frontmatter 의 `step` 은 스키마에 없어서 버려지고 있다
- 카테고리는 `topic` 값으로 정한다 (`network`, `boj` …). 폴더 목록과 이름 · 글리프는 `sections/posts/data.ts` 한곳에서 관리한다. 목록에 없는 topic 은 "기타" 폴더로 모은다
- 요약 : frontmatter `description` 이 있으면 그것, 없으면 본문 앞부분을 글자 140자까지 잘라 쓴다 (주석 `%% %%` · 이미지 · 코드 블록 제외)
- `docs/content-rules.md` 의 posts 예시에 `step` · `tier` · `description` 을 더한다

# 위키 (/wiki/) 그래프 읽기 화면 설계

작성 : 2026-11-27
목업 : 대화에서 확인한 `wiki-mockup.html` (C안 : 왼쪽 카테고리 트리 · 가운데 글 · 오른쪽 그래프 카드 + 목차 · 역링크)

## 1. 의도

허브 오른쪽 입구로 들어오는 위키를 옵시디언처럼 "노트가 이어진 그래프 위에서 읽는" 화면으로 바꾼다. 지금 `/wiki/` 는 분야별 링크 목록, `/wiki/<slug>` 는 사이트 기본 다크 읽기 틀 + 아래 역링크 목록뿐이다. 기존 Quartz 위키를 대신한다.

## 2. 목표 · 비목표 · 반목표

목표
- 위키는 컴퓨터 하나로 본다. 분야 (field) 로 나누지 않고 `topic` 으로 카테고리를 나눈다
- 첫 화면 (`/wiki/`) : 왼쪽 카테고리 목록 + 가운데 전체 그래프. 같은 카테고리 노트끼리 모인다
- 카테고리를 누르면 그 무리로 그래프가 부드럽게 확대되고 (다른 노드는 옅어짐), 왼쪽에 그 카테고리의 노트 목록이 펼쳐진다. 다시 누르거나 Esc 면 전체로. 주소에 `?topic=` 로 남는다
- 글 화면 (`/wiki/<slug>`) : 왼쪽 카테고리 트리 (지금 글의 카테고리가 펼쳐지고 지금 글 강조), 가운데 글, 오른쪽 위 그래프 카드 + 아래 목차 · 역링크
- 글 화면 그래프는 지금 글 중심 2단계 로컬 그래프이고, 지금 글이 카드 정중앙에 온다
- 첫 화면 → 글로 들어가면 그래프가 가운데에서 오른쪽 카드로 줄어들며 옮겨 간다
- 아직 없는 노트 (해석 안 되는 링크) 는 점선 빈 점. 이름은 확대 · 호버 때만
- 기술 블로그 글 노드 : 노란 정사각형. 그래프 오른쪽 위 버튼으로 켜고 끈다. 기본은 첫 화면 끔 / 글 화면 켬, 두 상태를 따로 브라우저에 기억
- 본문 링크 · 역링크에 호버하면 그래프의 그 노드와 이웃이 밝아진다
- 노드는 끌 수 있고, 위키 노드를 누르면 그 글로, 글 노드를 누르면 `/posts/<slug>` 로 간다
- 이름표는 화면 픽셀 기준으로 서로 · 점과 겹치지 않게 아래 → 위 → 오른쪽 → 왼쪽 자리를 찾고, 없으면 숨긴다 (호버하면 우선)
- 양 옆 칸 너비는 경계선을 끌어 조절 (왼쪽 180 ~ 420px, 오른쪽 220 ~ 520px), 더블클릭으로 기본값, 브라우저에 기억. 그래프 카드는 오른쪽 칸 너비의 정사각형
- 색은 기술 블로그 바탕화면 (`sections/posts/desktop.css`) 과 같은 계열
- 모바일 (860px 이하) : 카테고리는 위쪽 가로 칩, 글 화면 그래프는 글 위 220px 띠, 목차 · 역링크 패널은 숨김

비목표
- 철학 · 종교학 위키. 생기면 그때 나눈다
- 위키 검색. 허브 위쪽 검색 입구가 맡는다
- 노트 본문 스타일 개편. 지금 `article.css` 를 그대로 쓰고 색만 위키 토큰을 따른다

반목표
- 그래프 이름표끼리 겹쳐 읽을 수 없는 것
- 글이 그래프 밑으로 지나가며 겹쳐 보이는 것 (모바일)
- 글 노드가 첫 화면에서 카테고리 무리를 섞어 버리는 것 (그래서 기본 끔)

## 3. 제약

- 콘텐츠는 `wiki` · `posts` collection, 링크 해석은 `lib/content/graph.ts` 그대로
- 방 구조 규칙 : `sections/wiki/` (Layout.astro + tokens.css) + `pages/wiki/`
- 모든 화면 전환은 부드럽게, `prefers-reduced-motion` 이면 짧게
- 디자인에 요청하지 않은 설명글을 넣지 않는다

## 4. 접근

고른 안 : 빌드 때 그래프 데이터를 만들고, 그리기는 `d3-force` React 섬 하나가 맡는다. 섬은 `transition:persist` 로 페이지를 넘어 살아남아 노드 자리를 유지하고, `view-transition-name` 으로 가운데 → 카드 이동을 View Transitions 가 잇는다.

생각한 다른 안
- 목업처럼 직접 짠 힘 배치 : 의존성은 없지만 노드가 늘면 충돌 · 수렴을 손봐야 한다
- 빌드 때 좌표까지 계산 : 첫 화면이 안정적이지만 끌기 · 다시 자리 잡기 맛이 없어진다

## 5. 정한 것

- 데이터 : `lib/content/wiki-graph.ts` 의 순수 함수가 노드 (`id` = 주소, 아직 없는 노트는 `?` + 소문자 이름) · 선 · 카테고리를 만든다. 위키 노트와, 위키를 링크한 글만 넣는다. 아직 없는 노트는 위키 노트 본문에서만 나온다
- 카테고리 이름 : `sections/wiki/topics.ts` (예 : `network` → 네트워크). 목록에 없는 topic 은 원래 값, topic 이 없으면 "기타"
- 역링크 : 위키 노트와 글 모두 (`graph.backlinks` 확장)
- 본문의 깨진 위키 링크 (`span.wikilink-broken`) 에 `data-target` 을 붙여 그래프의 빈 점과 잇는다
- 목차 : `render()` 의 headings (h2 ~ h4), 스크롤 위치에 따라 지금 읽는 제목 강조
- 홈 버튼 : 기술 블로그처럼 작은 보라 선 버튼, 왼쪽 칸 위

## 6. 짓는 사람에게 맡긴 것

- 힘 세기 · 거리 같은 수치, 카테고리 중심 배치
- 그래프 카드의 2단계 노드가 너무 많을 때 줄이는 규칙
